> 我最后是做了一个完整的**题库算法标签分类系统**：它可以抓取 Codeforces 和洛谷的题目数据，按算法标签分类，保存成 JSON / CSV，再用图表把标签分布、难度分布和标签共现关系展示出来。
>

## 一、这个系统到底做什么

项目在 `07-数据分析通识教育/` 目录下，是一个 Flask 网站。启动后，浏览器里有四个主要视图：

| 页面 | 作用 |
|---|---|
| 题库看板 | 抓取题库、按算法标签筛选题目、查看难度和热度 |
| 知识图谱 | 把 HTML、DOM、requests、JSON、BeautifulSoup、re、反爬等概念连成一张网 |
| 双源对比 | 对齐 Codeforces 英文标签和洛谷中文标签，比较两个题库的算法偏重 |
| 爬虫原理 | 解释“取 → 解 → 分类 → 存”的流水线，并演示 API 和 HTML 两种爬法 |

项目的爬虫部分主要分成两个文件：

```text
cf_crawler.py       # Codeforces：官方 API / JSON 路线
luogu_crawler.py    # 洛谷：HTML 页面 / script 内嵌 JSON 路线
```

这两个数据源很适合放在一起讲，因为它们刚好代表了爬虫里两条常见路线：

1. **有 API 就先用 API**：Codeforces 提供官方接口，返回结构化 JSON。
2. **没有 API 就分析网页结构**：洛谷题库页面里有 HTML，真实数据藏在 `<script id="lentille-context">` 里。

所以这个项目不是简单“抓一个网站”，而是把“真实爬虫应该先判断数据在哪里”这件事做了出来。

## 二、Codeforces 路线：有 API 就别硬爬 HTML

先看 Codeforces。它提供官方公开接口：

```python
API_URL = "https://codeforces.com/api/problemset.problems"
```

核心请求函数如下：

```python
def fetch_problemset(timeout=30):
    """调 Codeforces API，返回解析后的 result 字典。"""
    r = requests.get(API_URL, headers={"User-Agent": BROWSER_UA}, timeout=timeout)
    data = r.json()
    if data.get("status") != "OK":
        raise RuntimeError(f"Codeforces API 返回非 OK：{data.get('comment', data.get('status'))}")
    return data["result"]
```

这里的逻辑很直白：

| 代码 | 含义 |
|---|---|
| `requests.get(...)` | 发起 HTTP GET 请求 |
| `headers={"User-Agent": BROWSER_UA}` | 带浏览器 UA，避免默认 Python 请求头太突兀 |
| `r.json()` | 把服务器返回的 JSON 转成 Python 字典 |
| `data["result"]` | 取出题目列表和通过数统计 |

这里有一个很重要的工程习惯：

> 如果目标网站已经提供稳定 API，就不要为了“看起来像爬虫”而硬爬 HTML。

API 的优点是字段清楚、结构稳定、请求次数少，也更不容易给目标网站造成压力。  
所以 Codeforces 部分的教学点不是“强行解析页面”，而是：**先判断有没有更合适的数据入口**。

## 三、Codeforces 数据怎么清洗

Codeforces API 返回的数据有两块：

- `problems`：题目信息，比如题号、名称、难度、标签。
- `problemStatistics`：每题通过数。

这两块需要用 `(contestId, index)` 对齐。代码里是这样处理的：

```python
def parse_problems(result):
    solved_map = {}
    for s in result.get("problemStatistics", []):
        solved_map[(s.get("contestId"), s.get("index"))] = s.get("solvedCount", 0)

    problems = []
    for p in result.get("problems", []):
        cid, idx = p.get("contestId"), p.get("index")
        if cid is None or idx is None:
            continue
        rating = p.get("rating")
        problems.append({
            "id": f"{cid}{idx}",
            "contestId": cid,
            "index": idx,
            "name": p.get("name", ""),
            "rating": rating,
            "diff_label": str(rating) if rating else "—",
            "diff_color": rating_color(rating),
            "tags": p.get("tags", []),
            "solved": solved_map.get((cid, idx), 0),
            "url": PROBLEM_URL.format(cid=cid, idx=idx),
        })
    return problems
```

这一步叫**字段清洗**。原始数据来自网站，字段结构不一定刚好适合前端展示，所以我把它整理成统一格式：

```python
{
    "id": "231A",
    "name": "Team",
    "rating": 800,
    "tags": ["brute force", "greedy"],
    "solved": 438327,
    "url": "https://codeforces.com/problemset/problem/231/A"
}
```

后面的分类、筛选、排序、可视化都基于这个统一结构完成。

## 四、洛谷路线：网页里藏着 JSON

Codeforces 是舒服的 API 路线，洛谷更像教材里真正要练的网页分析。

洛谷题库页表面上是 HTML，但题目数据不是普通表格，而是藏在这个标签中：

```html
<script id="lentille-context" type="application/json">
  {"data": {"problems": ...}}
</script>
```

所以洛谷爬虫的流程是：

![洛谷 HTML 内嵌 JSON 解析流程](/images/crawler-teaching-system/luogu-pipeline.png)

先抓一页 HTML：

```python
def fetch_page(page=1, timeout=20):
    # 这里抓取某一页 html，返回状态码和网页文本 HTML
    url  = LIST_URL.format(page=page)
    resp = requests.get(url, headers={"User-Agent": BROWSER_UA}, timeout=timeout)
    return resp.status_code, resp.text
```

这句：

```python
url = LIST_URL.format(page=page)
```

就是把 URL 模板里的 `{page}` 替换成当前页码。  
例如 `page=3` 时，实际请求：

```text
https://www.luogu.com.cn/problem/list?page=3
```

`fetch_page()` 只负责“取”，不负责解析。这个分工很重要。

## 五、最关键的 `_extract_context`

洛谷数据提取的关键函数是：

```python
def _extract_context(html): 
    # 从 HTML 里取出 <script id="lentille-context"> 的 JSON 数据
    pattern = r'<script id="lentille-context"[^>]*>(.*?)</script>'
    
    match = re.search(pattern, html, re.S)
    if not match: 
        raise RuntimeError("页面未找到")
    
    json_text = match.group(1)

    return json.loads(json_text)
```

为什么叫 `_extract_context`？

- `extract` 是提取。
- `context` 是页面上下文数据。
- 前面的 `_` 表示这是本文件内部使用的辅助函数。

正则表达式里比较重要的是这几段：

| 片段 | 含义 |
|---|---|
| `<script id="lentille-context"` | 找到指定 script 标签 |
| `[^>]*` | 允许 script 标签里还有其他属性 |
| `(.*?)` | 把 script 里面的 JSON 内容单独抓出来 |
| `re.S` | 让 `.` 可以匹配换行，因为 JSON 可能跨很多行 |
| `match.group(1)` | 取第一个括号里匹配到的内容，也就是 JSON 字符串 |

最后：

```python
json.loads(json_text)
```

把 JSON 字符串转成 Python 字典。  
这一步就是第六章里“从网页中提取结构化数据”的核心。

## 六、洛谷题目怎么变成统一格式

拿到 `context` 后，题目数据在：

```python
problem_block = context["data"]["problems"]
```

`problem_block` 是一个字典，大概长这样：

```python
{
    "count": 12345,
    "result": [
        {
            "pid": "P1000",
            "name": "超级玛丽游戏",
            "difficulty": 1,
            "tags": [2, 108],
            "totalAccepted": 680000
        }
    ]
}
```

所以 `problem_block["result"]` 才是真正的当前页题目列表。

洛谷还有一个额外麻烦：题目里的标签是数字 ID，不是中文标签名。  
因此要先请求：

```python
TAGS_URL = "https://www.luogu.com.cn/_lfe/tags"
```

建立两个东西：

```python
idToName = {}    # 标签 ID -> 标签名
algoIds = set()  # 算法标签 ID 集合
```

然后在 `parse_problems()` 里翻译标签：

```python
tagNames = []

for tagId in item.get("tags", []):
    if tagId in algoIds: 
        tagNames.append(idToName.get(tagId, str(tagId)))
```

最后清洗成和 Codeforces 一样的字段：

```python
problems.append({
    "id"        : pid,
    "name"      : name,
    "rating"    : difficulty,
    "diff_label": diff_label,
    "diff_color": diff_color,
    "tags"      : tagNames,
    "solved"    : accepted,
    "url"       : PROBLEM_URL.format(pid=pid),
})
```

这里我故意让洛谷也使用 `rating` 字段。虽然洛谷本身是 0-7 的难度等级，不是 Codeforces 那种 800-3500 的 rating，但这样前端就能复用同一套筛选和可视化逻辑。

## 七、分页抓取和限速

单页解析完，就可以把它串成完整爬虫：

```python
def crawl(pages=16, delay=0.12):
    """逐页抓取并解析洛谷题库。返回 (题目列表, 全站总数)。"""

    idToName, algoIds = fetch_tag_map()

    all_problems = []
    total = 0

    for page in range(1, pages + 1):
        status, html = fetch_page(page)

        if status != 200:
            break

        problems, total = parse_problems(html, idToName, algoIds)

        if not problems:
            break

        all_problems.extend(problems)

        time.sleep(delay)

    return all_problems, total
```

这里有两个细节：

1. `all_problems.extend(problems)` 用来把当前页题目合并到总列表里。不能用 `append`，否则会多套一层列表。
2. `time.sleep(delay)` 是简单限速。真实爬虫不能像压力测试一样连续猛打网站，这既不礼貌，也容易触发反爬。

## 八、分类与可视化：数据要能看懂

爬到题目之后，系统按算法标签分类。一道题可能有多个标签，所以它会进入多个分类桶：

```python
def classify_by_tag(problems):
    buckets = defaultdict(list)
    for p in problems:
        for tag in p["tags"]:
            buckets[tag].append(p)
    return dict(buckets)
```

有了分类，就能做统计和可视化：

- 标签分布 Top 20。
- 难度直方图。
- 标签共现网络。
- 难度 × 标签热力图。
- 标签平均难度 / 平均通过数散点图。
- Codeforces 与洛谷双源对比。

下面这张图来自项目保存的真实 Codeforces 数据：

![Codeforces 算法标签分布](/images/crawler-teaching-system/cf-tag-distribution.png)

从图里能看到，`greedy`、`math`、`implementation`、`dp` 是题量最多的几个主题。  
这说明可视化不是为了“看起来炫”，而是帮助我们快速理解题库结构：哪些知识点最常出现、哪些标签适合入门刷题、哪些标签通常更难。

## 十、存储：JSON 给程序，CSV 给人

爬虫结果最终会落盘：

```python
with open(json_path, "w", encoding="utf-8") as f:
    json.dump(problems, f, ensure_ascii=False, indent=2)

with open(csv_path, "w", encoding="utf-8-sig", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["题号", "名称", "难度", "通过数", "算法标签", "链接"])
```

这里也有两个中文数据处理的小细节：

- JSON 用 `ensure_ascii=False`，这样中文不会变成 `\u4e2d\u6587`。
- CSV 用 `utf-8-sig`，这样 Excel / WPS 打开中文不容易乱码。

系统还支持导出自定义的题库快照：

```text
tagbank-snapshot/v1
```

这个快照包含来源、抓取时间、题目数量、标签数量、分类索引、难度分布和全量题目。也就是说，别人拿到这个 JSON 文件，不打开网站也能理解这次爬取结果。

## 十一、测试：别只相信“页面能打开”

项目里还有一组 pytest 测试，覆盖了后端关键逻辑：


测试重点包括：

- Codeforces API 返回结果是否正确解析。
- HTML 表格能否用 BeautifulSoup 解析。
- 洛谷 `lentille-context` 能否从 HTML 中提取。
- 标签 ID 是否正确转成中文。
- Flask 接口返回结构是否符合前端需要。
- 导出 JSON / Markdown 是否可用。

我最后跑出来是：

这个环节很重要，因为爬虫项目特别容易出现“今天能跑，明天页面一变就炸”的问题。测试至少能保证：只要输入结构符合预期，解析函数和接口层就是稳定的。

## 十三、结语

这个项目最大的收获不是“我会写 requests.get 了”，而是理解了爬虫真正要做的判断：

> 数据在哪里？  
> 是 API 返回的 JSON，还是 HTML 里的 DOM，还是 script 里嵌着一段 JSON？

Codeforces 告诉我：有官方 API 时，直接走 API 是更稳、更克制的选择。  
洛谷告诉我：没有明显 API 时，就要分析页面结构，从 HTML 中找到真正的数据入口。  

最后，爬虫不是终点。把数据抓下来之后，还要清洗、分类、保存、可视化，才真正变成一个可用的系统。这个题库分类系统就是把第六章的知识点串成了一条完整链路：

```text
requests 获取 → HTML / JSON 解析 → 字段清洗 → 标签分类 → 文件存储 → 可视化应用
```

这也正是我觉得这次作业最有价值的地方：它不是只写了一个函数，而是把“爬虫如何服务数据分析”这件事完整跑了一遍。
