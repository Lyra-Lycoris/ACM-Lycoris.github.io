## 一、先说人话：爬虫到底在爬什么

打开一个网页，浏览器拿到的其实是一坨 **HTML 文本**。这坨文本由一层套一层的**标签**组成，浏览器把它解析成一棵 **DOM 树**再渲染给你看。

```
<li class="cat-post-item">
  <a class="cat-post-link" href="/posts/...">
    <span class="cat-post-title">标题</span>
    <time class="cat-post-date" datetime="2026-06-07">26-06-07</time>
  </a>
</li>
```

你在页面上看到的"标题、日期、标签"，在 HTML 里都是有固定结构的标签。**爬虫做的事，就是把网页这张"网"，抽成一张结构化的"表"**——把藏在标签里的数据提出来，存成 CSV 或 JSON。

所以一只爬虫的标准流程是四步，我把整个系统也按这四步搭：

> **取** 数据 → **解** 析 → **存** 储 → （进阶）**发** 数据

下面一步步来。

## 二、取数据：requests 与那个绕不开的 403

最基础的一步：把网页"拿"下来。用 `requests`：

```python
# crawler.py
SITE = "https://acm-lycoris.cn"

BROWSER_UA = ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
              "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120 Safari/537.36")

def fetch(url, with_headers=True, timeout=15):
    """with_headers=False 时不带浏览器 UA，用于演示「带/不带 UA」的请求差异。"""
    headers = {"User-Agent": BROWSER_UA} if with_headers else {}
    return requests.get(url, headers=headers, timeout=timeout)
```

逐行看：

- `requests.get(url, headers=...)` 发一个 HTTP GET 请求，返回一个 `Response`。
- `r.status_code` 是**状态码**：`200` 成功、`404` 没找到、`403` 被拒绝。
- `headers` 里那个 `User-Agent`，是在告诉服务器"我是谁"。默认情况下 requests 会老老实实写上 `python-requests/2.x`——等于举着牌子说"我是爬虫"。把它换成浏览器的 UA，就是最基础的**伪装**。

### 关于 403，我踩了个有意思的坑

做这个作业时我先用一个**云端工具**去抓自己的博客，结果吃了个 **403 Forbidden**。我一度以为"博客对默认 UA 直接拒绝"，还把这写进了系统。

但等我在**本机**用 `requests` 真跑一遍，发现——**不管带不带 UA，全都返回 200**：

```text
empty dict {}            -> 200  (UA: python-requests/2.34.2)
explicit curl            -> 200  (UA: curl/8.0)
browser                  -> 200  (UA: Mozilla/5.0 ...)
```

为什么？因为这个博客挂在 **Cloudflare** 后面。Cloudflare 的反爬**主要看 IP 来源**：从**云端/数据中心 IP**（典型的服务器爬虫）访问，会被弹验证挑战、返回 403；从**住宅 IP**（我自己电脑）访问就放行。

所以这件事的真正教训是：

> **反爬不只看 User-Agent，还看 IP 来源和访问频率。** 带上规范的浏览器 UA 是面对反爬的第一步好习惯，但它不是万能钥匙。

系统里我把这点如实做了出来——现场爬虫那栏会显示**这次实际发出去的请求头**和**真实状态码**，并讲清 Cloudflare 这层真相，而不是骗你"不带 UA 就一定 403"。诚实地讲一个真实现象，比演一个假的更有教学价值。

## 三、解析：BeautifulSoup 用选择器精准定位

页面拿到了，是一大坨字符串。`BeautifulSoup` 把它解析成 DOM 树，然后用 **CSS 选择器**精确定位要的标签：

```python
# crawler.py
def parse_articles(html):
    soup = BeautifulSoup(html, "html.parser")
    articles = []
    for a in soup.select("li.cat-post-item a.cat-post-link"):
        title_el = a.select_one("span.cat-post-title")
        date_el = a.select_one("time.cat-post-date")
        if not title_el:
            continue
        articles.append({
            "title": title_el.get_text(strip=True),
            "url": a.get("href", ""),
            "date": (date_el.get("datetime") if date_el else "") or "",
        })
    return articles
```

- `soup.select("li.cat-post-item a.cat-post-link")`：选出所有「文章列表项里的链接」，一次拿一批。
- `select_one(...)`：在每个链接里再精确定位标题、日期那一个元素。
- `get_text(strip=True)` 取标签里的文字，`get("href")` 取属性。

跑下来，首页 24 篇文章的标题、链接、日期就都结构化出来了。

## 四、正则 re：抠那些零碎字段

不是所有东西都适合用选择器。有些零碎信息，用**正则表达式**按模式直接从文本里抠更快。系统用它抓首页所有标签链接：

```python
# crawler.py
def extract_tags(html):
    pairs = re.findall(r'href="(/tags/([^"/]+)/?)"', html)
    seen = {}
    for url, raw in pairs:
        name = htmllib.unescape(unquote(raw))   # 先解 HTML 实体，再解 URL 编码
        url = url if url.endswith("/") else url + "/"
        if name and name not in seen:
            seen[name] = {"name": name, "url": url}
    return list(seen.values())
```

这里有个中文爬虫的常见小坑：URL 里的中文是**编码过**的（`%E4%B8%83...`），HTML 里的 `+` 号又会被写成实体 `&#43;`。所以 `name` 要先 `html.unescape` 解实体，再 `urllib.parse.unquote` 解 URL 编码，才能还原成"七夕祭""c++"这样的人话。

## 五、下钻：进文章页拿"真实标签"（关系图的关键）

这是我做可视化时发现的一个**坑点**，也是这个系统最值得讲的一处。

一开始我想偷懒：用"标签名是否出现在文章标题里"来连"文章—标签"的关系。结果惨不忍睹——20 个标签只有 3 个能在标题里匹配上，关系图稀稀拉拉只有 5 条边。因为首页只有一团**全站标签云**，它并不知道**哪篇文章挂了哪些标签**。

真实的"文章↔标签"关系，藏在**每一篇文章自己的页面里**。所以得**下钻**——挨个进文章页去抓：

```python
# crawler.py
def fetch_article_tags(article_url, with_headers=True, timeout=15):
    """抓单篇文章页，解析它真实挂的标签名列表。"""
    url = article_url if article_url.startswith("http") else SITE + article_url
    resp = fetch(url, with_headers=with_headers)
    if resp.status_code != 200:
        return []
    return [t["name"] for t in extract_tags(resp.text)]
```

后端编排时，对每篇文章都下钻一次：

```python
# app.py · run_crawl
for a in articles:
    a["tags"] = crawler.fetch_article_tags(a["url"], with_headers=with_headers)
```

代价是多发了 24 个请求（一篇一个），但换来的是**真实的关系数据**：从 5 条边变成 **136 条边**。这就是爬虫里"列表页 → 详情页"的经典下钻模式。

## 六、存储：CSV 与 JSON

抓到的数据要落盘。两种常用格式：

```python
# crawler.py
def save(data, fmt, name, out_dir="saved_data"):
    os.makedirs(out_dir, exist_ok=True)
    path = os.path.abspath(os.path.join(out_dir, f"{name}.{fmt}"))
    if fmt == "json":
        with open(path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    elif fmt == "csv":
        fields = list(data[0].keys()) if data else []
        with open(path, "w", encoding="utf-8-sig", newline="") as f:
            w = csv.DictWriter(f, fieldnames=fields)
            w.writeheader(); w.writerows(data)
    return path
```

两个中文小细节：

- JSON 要 `ensure_ascii=False`，否则中文会变成 `\uXXXX`。
- CSV 用 `utf-8-sig`（带 BOM），否则 Excel 打开会乱码。

## 七、可视化：把抓到的网，画成一张网

有了真实的"文章—标签"关系，后端把它组织成节点和边，前端用 **ECharts** 画力导向图：

```python
# app.py · build_viz（节选）
for a in articles:
    nodes.append({"id": "A:" + a["title"], "name": a["title"], "category": 0})
    for tag in a.get("tags", []):
        # 标签去重成节点，文章—标签连一条边
        links.append({"source": "A:" + a["title"], "target": "T:" + tag})
        counts[tag] += 1
```

最终是一张 **79 节点 / 136 边**的关系网：文章是一类节点，标签是另一类，谁挂了谁一目了然。词频条形图也跟着出来——「贪心」「图论」各 8 篇排在最前，正好对得上我这博客的算法底色。

> 这一步特别呼应开头那句话：网页本身是一张 DOM 网，博客内容是一张标签网，**爬虫的本质就是把一张网，抽取成另一张结构化的网**。

## 八、不止于"取"，还能"发"：POST 一条评论

爬虫不只会 GET 取数据，也能 POST **发**数据。我的博客评论用的是 **Waline**，提交评论就是往它的接口 POST 一段 JSON：

```python
# crawler.py
WALINE = "https://acm-lycoris-waline.vercel.app"

def build_comment(nick, mail, comment, url_path=COMMENT_PAGE_PATH):
    return {
        "method": "POST",
        "endpoint": WALINE + "/api/comment",
        "headers": {"Content-Type": "application/json", "User-Agent": BROWSER_UA},
        "body": {"nick": nick, "mail": mail, "link": "",
                 "url": url_path, "comment": comment, "ua": BROWSER_UA},
    }

def post_comment(preview, dry_run=True, timeout=15):
    if dry_run:                       # 默认只预览，绝不发送
        return {"sent": False, "preview": preview}
    r = requests.post(preview["endpoint"], json=preview["body"],
                      headers=preview["headers"], timeout=timeout)
    return {"sent": True, "status": r.status_code, "response": r.text[:500]}
```

注意那个 **`dry_run`**：默认 `True`，只把"将要发出的完整请求"展示给你看，**一个字节都不发**。只有你点了"真实发送"并确认，才会真的 POST。这样既能讲清"POST 表单/JSON"是怎么回事，又不会把测试评论刷满博客——演示对象就固定在《如果你想添加评论的话》那一篇。

## 十、结语

整个系统就是把爬虫的四步闭环走了一遍，每一步都能在界面上看见它真实发生：

| 模块 | 对应知识点 |
|------|-----------|
| ① 理论知识网络 | 网页结构 / DOM / 概念互联 |
| ② 现场爬虫 | requests、UA 与反爬真相、BeautifulSoup、re、下钻 |
| ③ 可视化 | 文章×标签真实关系图 + 词频 |
| ④ 发评论 | requests.post、表单/JSON 提交、dry_run 安全机制 |

做这个作业最大的收获，反而是那个 403 的坑：**把一个真实的、稍微复杂一点的现象讲清楚，比演一个干净的假象更有意思。** 网页是一张网，知识也是一张网，爬虫把它们连了起来。
