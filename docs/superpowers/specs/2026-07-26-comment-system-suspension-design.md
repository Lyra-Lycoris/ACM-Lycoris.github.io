# 评论系统暂停与公告设计

## 目标

因 Waline 评论后端持续产生云服务费用，在博客集中发布更多文章前暂时关闭评论功能，并通过独立公告向访客说明原因。

本次改动同时追求两个结果：

- 访客能够在首页及时看到评论暂停通知并进入完整公告页。
- 评论前端、样式、辅助脚本和后端请求不再进入页面加载链路。

## 页面与入口

新增独立公告页 `/notice/`，页面不属于 `posts` 内容分区，因此不会进入文章列表、归档、分类、标签或文章订阅。

首页主内容区域顶部增加一条轻量公告卡片，显示简短状态说明和“查看说明”链接。公告卡片沿用现有 Cyber-Reimu 的颜色、边框和排版变量，不引入图片、字体、JavaScript 或第三方资源。

公告属于临时运营状态，不新增主导航入口。评论恢复后，可以直接移除首页公告卡片，并更新或撤下独立公告页。

## 公告内容

公告页说明：

> 因评论系统持续占用较多云服务资金，而本站近期预算较为紧张，现暂时关闭评论功能。
>
> 这不会影响文章的正常发布与阅读。接下来本站将优先把有限的资源投入内容整理和文章更新，并计划在集中发布更多内容后，根据预算情况重新评估评论系统。
>
> 感谢理解，也感谢此前留下评论与建议的每一位读者。评论数据会妥善保留，评论功能恢复后将另行通知。

首页仅显示压缩后的提示文案，避免公告挤占文章列表：

> 评论系统因预算调整暂时关闭，不影响文章阅读与更新。

## 评论关闭方式

将站点配置中的 `waline.enable` 设为 `false`，保留现有 `serverURL` 和其他 Waline 参数，便于未来恢复。

现有 Hugo 模板以 `waline.enable` 和 `serverURL` 共同决定是否输出评论相关资源。关闭总开关后：

- 不输出评论区容器。
- 不输出评论初始化逻辑。
- 不加载 Waline 客户端模块。
- 不加载 Waline 样式。
- 不向 Waline 后端发起评论请求。

同时从全站 `body_end` 注入中移除 `waline-initial-avatar.js`。该脚本只服务于 Waline 评论头像，在评论暂停期间没有保留价值，也不应继续增加页面请求。

不删除 Waline 后端源码、服务配置或历史评论数据；本次仅调整博客前端的启用状态。

## 实现边界

本次包括：

- 一个独立公告内容页。
- 一个首页公告入口。
- 与现有风格一致的少量本地 CSS。
- Waline 总开关关闭。
- Waline 专用头像辅助脚本停止注入。
- 构建输出与资源加载验证。

本次不包括：

- 删除 Waline 后端源码或云端数据。
- 修改或关闭云服务控制台中的后端资源。
- 更换评论系统。
- 新增弹窗、轮播、动画或全站导航项。
- 改动已有文章内容。

## 验证

使用本地 Hugo 完整构建，并检查生成结果：

1. `/notice/` 对应页面成功生成。
2. 首页包含公告卡片和公告页链接。
3. 公告页不出现在普通文章列表和归档中。
4. 文章页不包含评论区容器。
5. 生成 HTML 不包含 Waline 客户端、Waline 样式、后端 URL 或 `waline-initial-avatar.js`。
6. 现有主要页面仍能成功构建，首页文章列表与文章详情页结构不受影响。
